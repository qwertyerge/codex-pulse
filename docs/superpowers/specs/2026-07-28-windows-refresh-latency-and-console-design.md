# Windows 刷新延迟与控制台弹窗设计

## 目标

本轮只处理两个问题：

- 刷新期间的新通知不能丢失，近期事件最多等待既有的 5 秒稳定期；
- Pulse 自己启动的 `git.exe` 在 Windows 上不得显示控制台窗口。

保留现有 60 秒兜底刷新、5 秒事件稳定规则、默认 Codex 周额度语义和
macOS 行为。本刷新/控制台 cohort 不处理额度展示和暗色页脚，Windows 0.3.0 验收范围内的窗口最大化也不在此 cohort 实施。

## 已确认原因

- `schedule_refresh` 在已有刷新运行时直接丢弃后续通知。
- 近期事件被 5 秒规则暂存后，没有到点唤醒，只能等待下一次 Hook。
- Git 补充信息在刷新链路中串行执行多个 `git.exe`，且未设置
  Windows 隐藏窗口标志。
- Codex 的 Windows 命令 Hook 还可能经过 `cmd.exe`；它不属于 Pulse
  的子进程边界，本轮先通过人工复测判断是否仍需方案 B。

## 实现设计

### 1. 三态刷新调度器

用一个原子三态替换当前布尔值：

- `Idle`：空闲；
- `Running`：正在刷新；
- `RunningPending`：正在刷新，结束后必须再补一次。

规则：

1. `Idle` 收到通知后进入 `Running` 并启动刷新。
2. `Running` 收到通知后进入 `RunningPending`。
3. `RunningPending` 继续收到通知时不增加任务。
4. 刷新结束时，`RunningPending` 回到 `Running` 并立即补一次；
   `Running` 回到 `Idle`。

成功和失败都必须完成状态转换，避免刷新永久卡住。

### 2. 5 秒稳定期到点唤醒

事件合并函数返回被暂存事件的最早到期时间。一个截止时间协调器只保留
一个有效唤醒；旧定时器被替代后不再触发刷新。到点后仍通过同一三态
调度器刷新，避免并发扫描。

近期事件合并使用最早截止时间，避免后续事件延迟已经等待的刷新；命令 Hook 的 transcript settle 使用最新截止时间，保证最后一次写入后保留完整静默期。

### 3. 隐藏 Git 子进程

`ProcessGitRunner` 继续直接执行 Git。仅在 Windows 下为命令添加
`CREATE_NO_WINDOW`，不改变输出捕获、超时、退出码和其他平台行为。

### 4. 调试耗时

仅调试构建记录额度扫描、会话扫描、Git 补充和总刷新耗时。日志不得包含
提示词、会话正文、凭据、额度值或远程地址。

## 测试

先写失败测试，再实现：

- 空闲通知启动刷新；
- 刷新中多个通知只补一次；
- 成功或失败后都能正确回到空闲；
- 5 秒内返回到期时间，到期边界立即采用新事件；
- Windows Git 命令带隐藏窗口标志；
- 现有 Git 输出、错误和超时行为不回退。

随后运行 Rust 全量测试、前端测试和前端构建。现有 Windows 基线问题
单独报告，不通过放宽断言掩盖。

## 人工验收

开发版自动重启后：

1. 发送一条 Codex 消息，确认不再等待约 10 秒；
2. 快速触发多个工具事件，确认最终状态不丢失；
3. 连续更新时观察桌面，确认不再闪出 Pulse 的 Git 控制台；
4. 确认托盘和正常界面行为未回退。

若仍有弹窗，则单独设计方案 B：Windows 改用文件监听并安全移除
Pulse 命令 Hook。本分支不直接扩大到该架构变更。
