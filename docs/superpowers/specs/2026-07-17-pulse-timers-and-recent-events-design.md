# Codex Pulse：计时器与最近事件设计

## 目标

让窗口标题就近显示活跃会话数；让运行计时器稳定逐秒递增；在每张活跃会话卡片中显示一条经节流的最近有意义事件。

## 范围

- 左上角 `Codex Pulse` 文案之后显示 `N active`；右侧只保留 Pin/Unpin。
- 运行计时使用前端单调时钟，避免异步刷新造成重复秒或回跳。仅当 `currentRunStartedAtMs` 变更时，视为新运行并重置该卡的计时基准。
- 每个根会话聚合自身与子会话的事件，只显示最新一条有意义事件。
- 有意义事件采用高信号优先级：`agent_message`（正式进展）优先；随后是补丁应用结果、MCP/网页搜索结果、任务完成与子代理完成。忽略 `agent_reasoning`、`token_count`、裸 `exec` 完成等内部或低信息量记录。
- 每会话的展示事件以 5 秒为合并窗口：窗口内保留最后一条，窗口结束后更新卡片。
- 无有意义事件时不渲染最近事件区域。
- 最近事件默认显示一行摘要和全小写相对时间（如 `18s ago`）。点击该行展开完整摘要；展开时冻结该会话的事件内容和相对时间，直到用户收起。其他会话继续刷新。

## 数据流

JSONL 解析层保留生命周期事件，并将高信号事件归纳为可展示的摘要、时间和来源线程。注册表将子会话事件归并到根会话，并按优先级与时间挑选记录。应用状态在刷新快照时按根会话维持 5 秒的展示事件节流，再将结果返回前端。前端的展开状态仅冻结对应卡片的展示快照，不影响后端继续采集或其他卡片刷新。

前端以 `performance.now()` 相对于快照收到时的墙钟锚点计算当前时间，并在下一个秒边界调度下一次更新。计时格式继续使用现有 `formatDuration`。

## 验收

- 会话数紧随左上标题，Pin/Unpin 不再与计数同组。
- 稳定运行时计时显示不重复、不倒退；新 run 开始时从新的起点计算。
- 卡片最多显示一条最近事件，且 5 秒内高频事件不连续闪动。
- 根会话能显示来自活跃子会话的最新有意义事件。
- 裸工具名 `Completed exec` 不再作为最近事件显示。
- 展开卡片时，其事件摘要与时间不变化；收起后恢复最新的节流事件。
- Rust、前端单元测试和构建保持通过。
